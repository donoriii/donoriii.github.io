PRIVACY POLICY

개인정보처리방침

이 문서는 계정 소유자가 직접 사용하는 개인용 Drive 백업 도구의 Google 사용자 데이터 처리 방식을 설명합니다.

Effective / updated: 2026-10-16

1. Purpose and data accessed

The utility is operated by its account owner for private project backup, version tracking and recovery checks. It may access the account email address and storage quota, file/folder identifiers and names, content selected for the task, MIME types, sizes, revisions and sharing/permission metadata. It does not request Gmail, Calendar or Contacts permissions in the current Drive backup workflow.

Google Drive data is used only to validate the intended account and destinations, execute explicitly authorized file operations, and verify backup integrity. Files outside the selected task are not intentionally processed for backup.

2. Storage and credentials

Selected files and nonsecret verification records may be stored locally. Project source backups go only to owner-approved private GitHub repositories; project data backups go only to registered private Google Drive destinations. The owner controls retention and deletion. OAuth credentials remain in access-restricted local storage. They must not be published to this documentation site or included in source/data backups. The utility does not operate a public credential-collection server.

3. Sharing, transfers and AI tools

Google API requests are sent to Google to perform the requested task. A transfer to a separately selected backup provider happens only as authorized by the owner and under that provider's terms. The utility does not sell Google user data or use it for advertising. The Drive client itself does not call AI model services or train AI models.

Separate AI assistants may receive task context or selected content when the owner chooses to use those tools. Their settings and provider terms must be checked separately. Google user data must not be used to develop, improve or train generalized AI/ML models, and any user-directed processing or transfer must comply with Google's Limited Use requirements.

The app's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

4. Security and retention

Google API traffic uses HTTPS. Local credentials use restrictive file access controls. The owner remains responsible for device security, backup destination permissions and reviewing authorized operations. No security control can guarantee protection against every incident. Nonsecret task records may include file metadata, revisions or integrity hashes; retention is controlled by the owner.

5. Your controls

The owner can stop using the utility, remove its local authorization, revoke the app's access in Google Account's third-party connections settings, and remove stored files/records from their selected destinations. Revoking authorization does not automatically delete previously created backup files. Before deleting a backup, the owner should check retention and recovery needs.

6. This documentation website

This GitHub Pages site contains app information, this policy and terms only. It has no login, uploads, forms, analytics scripts, advertising or application code that receives Google user data. GitHub may process ordinary hosting/security request information under its own policies. Site visitors do not need to authorize Google Drive.

7. Changes

Material changes to data use must be reflected here before they are introduced. The updated date identifies the current policy. This document concerns the current Drive backup workflow using the legacy OAuth registration name, not an unrelated public OpenClaw or Google Workspace service.
